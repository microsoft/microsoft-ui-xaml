Windows.UI.Composition API and behavior comparison

Baselines: Windows 11 21H2 build 22000 (UniversalApiContract v13) and Windows 11 build 26100 (UniversalApiContract v19). The latest local validation OS may be newer than 26100; metadata claims in this report stop at SDK 26100.

Executive result

The generated public metadata for Windows.UI.Composition.Core, .Desktop, .Diagnostics, .Effects, .Interactions, and .Scenes is identical between the two baselines. Only the root Windows.UI.Composition namespace changed. All observed changes are additive UniversalApiContract v15 APIs; no removals or signature mutations were found.

Compositor.CreateAnimationController() No Yes New v15 factory returning an existing AnimationController. The controller type itself existed since v6; the difference is direct construction without first starting an animation. Source initializes playback rate to 1, progress to 0, and default progress behavior. ANIM-005
CompositionObject.StartAnimation(String, CompositionAnimation, AnimationController) No Yes New v15 overload. It starts the normal property animator and adds that animator to the supplied controller when supported. Multiple animations can therefore share one progress/playback control object. The original two-parameter overload is unchanged. ANIM-006
CompositionTexture No Yes New v15 agile, both-threaded class deriving from CompositionObject and implementing ICompositionSurface. Created through ICompositorInterop2.CreateCompositionTexture, not a public projected Compositor factory. Microsoft documentation limits this API to Direct3D 11. The interop API exposes an availability fence for producer/compositor synchronization. TEX-001
CompositionTexture.SourceRect No Yes New read/write Windows.Graphics.RectInt32. It selects the sampled sub-rectangle of the backing texture. The current local implementation contains suspicious coordinate conversion: get assigns Y from left and put computes bottom from X. A non-zero, non-square round trip is therefore tested explicitly rather than assuming documented behavior. TEX-002
CompositionTexture.AlphaMode No Yes New read/write DirectXAlphaMode. It tells DWM whether texture alpha is honored. Source defaults the underlying texture to DXGI_ALPHA_MODE_IGNORE; the harness changes it to premultiplied. TEX-002
CompositionTexture.ColorSpace No Yes New read/write DirectXColorSpace. Source defaults to full-range G22 P709 and forwards changes to the presentation surface. TEX-002
ICompositionTextureInterop.GetAvailableFence No Yes New native interop synchronization surface. The source reports a fence only while the texture is available to the application; visual bindings make it unavailable until composition releases them. TEX-001
DirectXColorSpace dependency Not used by WUC Used The root Composition metadata now references Windows.Graphics.DirectX.DirectXColorSpace for CompositionTexture.ColorSpace. TEX-002

Expected cross-build result

On build 22000, all v13-or-earlier scenarios should run and the v15 scenarios should report NOT AVAILABLE. On build 26100, v15 scenarios should run. Any other result is a behavioral regression, environment limitation, or implementation defect and is retained in the generated JSON rather than normalized away.

Current runtime result

On the available Windows build 10.0.26200, 23 of 24 scenarios passed. The single failure was TEX-002: setting SourceRect to (7, 11, 31, 29) read back as (7, 7, 31, 25). This exactly matches the suspicious local implementation mapping and is retained as a product behavior finding. Build-22000 execution remains required on a separate machine; v15 tests are expected to report NOT AVAILABLE there.

Important: Microsoft Learn lists the v15 additions as introduced in Windows 11 Insider Preview build 23504. They must not be inferred to exist on all Windows 11 releases merely because the namespace itself exists.
