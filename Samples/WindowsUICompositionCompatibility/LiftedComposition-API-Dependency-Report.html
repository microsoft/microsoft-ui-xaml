The coupling is concentrated in XAML visual interop, composition animation, animated visuals, scrolling customization, brushes/lights/backdrops, and Content hosting. The stable documentation scan found no direct lifted-Composition signature in Microsoft.UI.Windowing, Microsoft.UI.Dispatching, Microsoft.UI.System, or stable Microsoft.UI.Input.

Scope rule: APIs declared inside Microsoft.UI.Composition* are intentionally excluded. Otherwise every Composition API would trivially qualify. An entry is counted only when a public declaration outside those namespaces directly names a lifted type, or when a class directly implements a lifted Composition interface.

Methodology and evidence boundary

  • Stable baseline: the current Microsoft Learn windows-app-sdk-2.0 moniker, corresponding to the current stable release channel.
  • Experimental entries use the Microsoft Learn windows-app-sdk-2.0-experimental moniker and are not mixed with stable totals.
  • Parameters, return values, properties, implemented interfaces, and protected override surfaces are included.
  • Documentation text that merely discusses Composition, without a Composition type in the declaration, is classified as indirect and is not counted.
  • Windows.UI.Composition signatures are listed separately as system counterparts and are not counted as lifted dependencies.
  • The “Function” column paraphrases the behavior documented on the linked Microsoft Learn page; it does not infer private implementation behavior.

Refactoring implications

A switch from lifted to system Composition cannot be limited to replacing compositor creation. It breaks public contracts in six distinct ways: returned visuals/compositors, accepted animation objects, implemented interfaces, protected brush/light extension points, scrolling animation customization, and Content hosting factories. The broadest source impact is inherited: UIElement and Brush expose lifted animation interfaces to every derived XAML type.

The Content namespace already documents parallel system-visual entry points for several island operations. Those APIs demonstrate that lifted and system visuals are treated as different object families; they are explicit alternatives, not namespace aliases. The experiment therefore needs coordinated public metadata changes and cannot rely on source-level type aliases alone.
