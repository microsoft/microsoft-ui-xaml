Logical grouping

Queue acquisition and lifetime

  • DispatcherQueue.GetForCurrentThread returns the queue currently bound to the calling thread.
  • DispatcherQueueController.DispatcherQueue returns the queue whose lifetime the controller manages.
  • Four shutdown events provide the queue as the typed event sender during queue and framework shutdown phases.

WinUI/XAML thread-affinity roots

  • DependencyObject.DispatcherQueue is inherited throughout the XAML object hierarchy.
  • Window.DispatcherQueue exposes the queue associated with a WinUI window and can be read from any thread.

Composition

  • CompositionObject.DispatcherQueue is inherited throughout the composition-object hierarchy.
  • Compositor.DispatcherQueue exposes the queue used by the compositor itself.

Input

  • InputObject.DispatcherQueue is the queue-affinity root for Windows App SDK input objects.
  • InputNonClientPointerSource.DispatcherQueue exposes the queue used for non-client pointer processing.

Windowing and display

  • AppWindow can return, accept, or be created with a supplied queue.
  • DisplayInformation.DispatcherQueue returns the queue associated with display-change notifications.

Content islands and sites

  • Content sites, site views, islands, and child links expose their associated queue.
  • ContentIsland.CreateForSystemVisual accepts the current thread's queue for a system visual root.

Desktop content bridges

  • The bridge interface and concrete desktop bridge types expose their queue.
  • Attached and child bridge factories accept a queue to establish thread affinity.

Documented .NET projection helper

DispatcherQueueSynchronizationContext(DispatcherQueue)

Microsoft’s Windows App SDK single-instancing guidance constructs Microsoft.UI.Dispatching.DispatcherQueueSynchronizationContext from DispatcherQueue.GetForCurrentThread(). It adapts a queue to .NET’s SynchronizationContext. This is listed separately because Microsoft documents its use but does not publish a dedicated Windows App SDK WinRT API-reference page for the constructor.

Important exclusions and boundary cases

  • DisplayInformation.CreateForWindowId(WindowId) and CreateForDisplayId(DisplayId) require the calling thread to already have a running lifted queue, but neither signature consumes nor returns DispatcherQueue.
  • DispatcherQueueController.CreateOnCurrentThread and CreateOnDedicatedThread create queues indirectly but return a controller, not a queue.
  • DispatcherQueue.EnsureSystemDispatcherQueue() manages Windows.System.DispatcherQueue; its signature does not consume or return the lifted type.
  • TryEnqueue, queue timers, run-loop methods, and shutdown methods operate on a queue instance but do not accept or return a DispatcherQueue.
  • Microsoft.UI.Input.Experimental.ExpInputObject.DispatcherQueue is documented only for the old Windows App SDK 0.8 moniker and is not part of the current 1.8 inventory.
  • Derived XAML, composition, input, and bridge classes inherit queue properties from their base declarations. Repeating every inherited appearance would inflate the list without adding API declarations.
